# 中点选择与地图路径展示设计

## 背景

当前实际启动入口是 `app/main.py`（FastAPI），`start.sh` 通过 Uvicorn
启动该应用；`static/index.html` 是共用的单页前端。根目录的
`app_v2.py` 是旧 Flask 入口，不是当前部署入口。本次实现以 FastAPI
版本为准，不顺带重构或覆盖工作区内已有的未提交改动。

当前搜索流程会计算一个中点，在中点周边搜索候选 POI，再为 A、B
分别计算到每个 POI 的路线。前端目前只能高亮候选地点和查看路线摘要，
不能让用户明确选择中点算法，也不会在地图上绘制 A、B 到候选地点的路径。

## 目标

1. 用户可以明确选择“位置中点”或“交通中点”，默认使用位置中点。
2. 位置中点模式保留 A、B 独立出行方式。
3. 交通中点模式只允许双方统一使用公交/地铁或统一使用驾车。
4. 点击候选地点卡片或标记时，在地图上显示 A、B 两条缓存路径：
   A 为蓝色，B 为橙色。
5. 首次搜索不返回所有路径坐标；路径保存在现有服务端 Session 中，
   点击时按单个候选地点读取，不再次请求高德。

## 非目标

- 不把根目录旧 Flask 入口改造成新的主入口。
- 不持久化 Session；继续使用现有进程内、1 小时 TTL 的缓存。
- 不提供逐步导航、语音导航或路径拖拽编辑。
- 不在首次搜索时渲染全部候选地点的路线。

## 中点模式

### 位置中点

前端发送 `midpoint_mode: "geo"`。后端直接使用 A、B 经纬度的地理
中心作为搜索中心，并返回现有建议搜索半径。A、B 可以继续分别选择：

- 最快
- 公交/地铁
- 骑行
- 驾车
- 步行

路线重算只更新候选地点的路线与排序，不改变位置中点坐标。

### 交通中点

前端发送：

```json
{
  "midpoint_mode": "transport",
  "prefer_a": "transit",
  "prefer_b": "transit"
}
```

或：

```json
{
  "midpoint_mode": "transport",
  "prefer_a": "driving",
  "prefer_b": "driving"
}
```

选择交通中点后，界面隐藏 A、B 独立方式，改为一个双方共用的二选一：

- 双方公交/地铁
- 双方驾车

选择会同步写入 `prefer_a` 和 `prefer_b`。后端仍做强校验：交通中点下，
两侧方式必须相同，且只能是 `transit` 或 `driving`；非法请求返回
HTTP 400 和可直接展示的中文错误，不静默改写用户输入。

后端沿 A→B 的所选实际路线建立“累计时间—坐标”序列，并取总耗时约
一半处的坐标作为交通中点。公交/地铁和驾车分别使用各自路线数据。
如果 A→B 没有可用路线或缺少轨迹，搜索降级到位置中点，并在响应的
中点元数据中返回 `fallback_reason`；前端展示一次非阻塞提示。

交通方式在重算面板中切换时，交通中点随新的统一方式重新计算。

## 后端数据流

### 搜索请求

`POST /api/v2/search` 新增字段：

```json
{
  "midpoint_mode": "geo"
}
```

允许值为 `geo` 和 `transport`。缺省值为 `geo`，使旧客户端保持可用。
该值贯穿 `run_pipeline`、搜索上下文和 Session。

每个进入路线计算的基础 POI 会获得一个会话内稳定、不可猜测业务含义的
`route_id`，例如 `r0`、`r1`。排序或路线重算不会改变该 ID。初始搜索
响应会返回 `route_id`，但不会返回路径坐标。

### 路径提取与缓存

现有高德路线调用在计算时间、距离的同时提取最终选中方式的轨迹，规范化为：

```json
{
  "mode": "transit",
  "segments": [
    {
      "mode": "walking",
      "path": [[116.1, 39.9], [116.11, 39.91]]
    },
    {
      "mode": "transit",
      "path": [[116.11, 39.91], [116.3, 39.95]]
    }
  ]
}
```

驾车、步行和骑行也使用同一结构。无效坐标、空段和连续重复点会在缓存前
移除。路径仅保留绘图所需的方式和坐标，不保存完整高德原始响应。

Session 新增：

```text
route_geometries[route_id].a
route_geometries[route_id].b
```

初始响应的 `transport_from_a`、`transport_from_b` 继续只包含时间、距离、
线路摘要和实际方式，不包含 `segments`。路线重算会整体替换相应 Session
中的路径缓存，避免时间摘要和地图路径不一致。

### 单地点路径接口

新增：

```text
GET /api/v2/session/{session_id}/routes/{route_id}
```

成功响应：

```json
{
  "success": true,
  "route_id": "r0",
  "route_a": {
    "mode": "driving",
    "segments": []
  },
  "route_b": {
    "mode": "transit",
    "segments": []
  }
}
```

会话不存在或过期返回 404；`route_id` 不属于该会话返回 404。单侧路线
失败时，该侧值为 `null` 并带 `errors.a` 或 `errors.b`，另一侧仍可绘制。
该接口只读 Session，不再次调用高德。

## 前端交互

### 中点选择

主搜索表单增加一个中点方式选择器：

- 位置中点（默认）
- 交通中点

位置中点下显示现有 A、B 独立出行方式。交通中点下显示双方统一方式，
默认选择公交/地铁，可切换为驾车。切回位置中点时恢复用户上次的 A、B
独立选择，而不是把交通中点的统一值永久覆盖。

重算面板使用相同规则并与主表单状态同步。

### 路径展示

点击候选卡片或候选地图标记都会：

1. 高亮候选地点。
2. 清除上一个地点的所有路径覆盖物和错误状态。
3. 显示 A、B 两侧的加载状态。
4. 使用当前 `session_id` 与 POI 的 `route_id` 请求单地点路径接口。
5. 将 A 的所有有效分段绘制为蓝色，将 B 的所有有效分段绘制为橙色。
6. 将地图视野调整到 A、B、目标地点和两条路径的联合范围。

两侧路径共用实线样式，通过颜色和一个小型图例区分。公交中的步行分段
仍使用所属出发方的颜色，避免一张地图出现过多视觉编码。

以下操作会清除当前路径：

- 点击另一个候选地点
- 发起新搜索
- 路线重算
- 改变显示数量后，当前候选已不在可见列表中
- 清除 A 或 B 出发地

接口只返回一侧有效路径时只绘制该侧，并显示另一侧失败提示。会话过期时
提示用户重新搜索。快速连续点击时使用请求序号忽略旧请求的迟到响应，
防止旧地点路径覆盖新地点。

## 错误处理

- 非法 `midpoint_mode`：HTTP 400，提示只支持位置中点或交通中点。
- 交通中点方式组合非法：HTTP 400，提示双方必须同时选择公交/地铁或驾车。
- 交通中点不可计算：降级位置中点，搜索继续，前端展示 `fallback_reason`。
- 路径缓存缺失：单地点路径接口返回明确的单侧错误，不触发新的地图 API 请求。
- Session 过期：路径接口返回 404，前端清除加载状态并提示重新搜索。
- 路径响应迟到：前端通过请求序号丢弃，不改变当前地图。

## 测试策略

后端自动化测试使用项目现有 Python 测试区，覆盖：

1. `geo` 模式始终调用位置中点，并允许 A、B 任意合法独立方式。
2. `transport` 只接受双方统一的 `transit` 或 `driving`。
3. 两种交通中点调用对应路线算法，失败时带原因降级。
4. 驾车、公交、步行、骑行原始响应都能规范化为分段路径。
5. 首次搜索和重算响应不包含路径坐标。
6. Session 按 `route_id` 保存 A、B 路径，重算后替换旧缓存。
7. 单地点路径接口处理成功、单侧缺失、未知 ID 和过期会话。

前端通过浏览器手工验证：

1. 两种中点模式的控件切换和状态恢复。
2. 交通中点只显示统一公交/驾车选择。
3. 点击卡片和地图标记都能显示蓝、橙两条路径。
4. 快速切换地点不会出现旧路径覆盖。
5. 新搜索、重算和清除地点会清除旧路径。
6. 单侧失败和 Session 过期提示可见且不阻塞另一侧。

## 兼容性与文件归属

计划修改：

- `app/main.py`：请求校验、中点模式分流、路径 Session 缓存与读取接口。
- `app/amap_client.py`：交通时间中点、四类路线轨迹提取与规范化。
- `static/index.html`：中点选择、统一交通方式、路径请求与覆盖物绘制。
- `tests/`：与上述行为对应的后端自动化测试。

不创建新的顶层源代码目录，不移动现有文件，不修改旧 Flask 入口。
